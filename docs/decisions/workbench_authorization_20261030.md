# Local Research Workbench - Principal Authorization

Status: **ADMITTED BY THE PRINCIPAL - DISPOSABLE SYNTHETIC DEVELOPMENT. CV1 UNCHANGED. CONSTITUTIONAL DELTA 0/0/0.**

Date: 2026-10-30. This record admits the
[local research workbench plan](../plans/local_research_workbench_20261030.md)
as answered by the
[workbench readiness audit](../audits/workbench_readiness_audit_20261030.md),
with two adjustments the Principal made before implementation. It is the
one authorization the plan asked for. No approval packet, run approval or
mandatory review round follows from it.

## Adjustments, verbatim

> Test reopening an unfinished run. Reopening two completed histories proves
> inspection. Close after the diagnostic, restart, and continue without
> repeating work or charges.
>
> Distinguish independent computation from independent evidence. Tool B
> reproducing counts on the same rows verifies the calculation. It does not
> supply new market observations. Make that distinction clear in the
> interface.

## Authorization, verbatim

> Build the local research workbench described in the plan. I authorize the
> local UI, synthetic cohort variants, session/reopen support and necessary
> implementation changes within this scope. Record that authorization
> briefly and proceed without another approval packet.
>
> Keep it simple: standard-library Python, loopback-only server and one HTML
> page. Use the real harness commands and persisted records. No scripted
> outcomes, direct database writes or browser-owned authority.
>
> Include the three proposed cohorts. Clearly distinguish Tool B reproducing
> a calculation from obtaining independent observations. Present descriptive
> thresholds as diagnostics, not statistical proof.
>
> Make the page readable: run selection, research sequence, evidence and
> budget summary. Put raw records and detailed accounting behind expandable
> sections. Use a compact, persistent synthetic/deterministic label rather
> than a large disclaimer panel.
>
> Verify an unfinished-run recovery: stop after the diagnostic, close the
> server, restart, reopen and continue without duplicating computation,
> charges or admission. Also verify completed histories and read-only
> inspection when the build differs.
>
> The session's list of next actions is a UI convenience. The core must
> still enforce permission and current-state checks when an action executes.
>
> Run the original example regression, all three cohort paths and focused
> workbench tests. Open the page in a browser and verify the actual
> interaction and layout. A separate reviewer is optional, not a new
> completion gate.
>
> No accounts, cloud deployment, real data, LLM calls or new infrastructure.
> Preserve existing records and unrelated work.
>
> Deliver the working page, the launch command, what you tested and any
> remaining limitations. Do not stop at another plan.

## Working rule, verbatim

> Build, test, show you the result. Brief records of meaningful decisions, no
> approval packets or mandatory review rounds for routine prototype work.
> Pause only for a substantive change to the harness's authority or meaning,
> real spending, production access, or publication.

## Effect

The first research-cycle plan's "broad UI work" exclusion is lifted for this
scope. Variant cohorts are declared synthetic Observations of the existing
`SRC-SYN` item `cohort-2026-10-28` with different bytes, which the source
declaration already classes as new Observations rather than replacements.
No grant, source, object kind, Transition class, Checker, tool or Rule
changes. Admitted records and the admission packet are untouched. Runtime
budget, authorization, Check, decision and Apply controls stay enforced by
the core on every action the page requests.
