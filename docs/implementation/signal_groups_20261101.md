## 1. The script

`examples/signal_groups/signal_groups.py`, 55 lines, standard library
only. It reads a CSV, sorts rows by a signal column, splits them into
equal groups and reports each group's row count, mean outcome and hit
rate as exact integer ratios, and the spread between the top and bottom
group means. It has no knowledge of ARH and its calculation was not
changed when it was connected.

Verified on its own by an independent float computation over the same
grouping and by a hand-worked four-row case, both in
`tests/integration/test_signal_groups.py`. The data,
`data/signals.csv` and `data/signals_more.csv`, 240 rows each, is
generated by `make_data.py` with a weak relation between a momentum
signal and a forward return, and is labelled synthetic in the source
declaration and on every record.

Baseline, run directly: spread 55.5 bp between the top and bottom
terciles over 240 rows, in about a millisecond of compute.

## 3. The experience, as run

`.venv/bin/python -m examples.signal_groups`, retained as
`artifacts/development/workbench/demo-20261101-signal-groups/`.

| Step | What happened |
| --- | --- |
| Startup | N=5 in 0.6 s, each control checked by the evaluator |
| Import | `signals.csv`, 240 rows, committed with its content hash |
| Expectation first | Design E23, "top tercile beats bottom tercile by at least 50 bp", recorded with no attempt |
| Run | The host ran the tool; spread 55.5 bp, equal to the direct run; conclusion MET; settled |
| Candidates | other-horizon, finer-groups, placebo-signal, from the MET rule and an empty history |
| Selection | placebo-signal chosen; other-horizon and finer-groups rejected with condition `new_documents` |
| Check, decide, apply | PASS, admitted, N=6, direction TH-S1 |
| Placebo | vol_60 against the same outcome, expectation "spread under 25 bp", spread 5.2 bp, MET |
| Candidates shaped by history | only placebo-signal live; the two rejected candidates held back until new documents arrive |
| New rows | `signals_more.csv` imported; both held-back candidates reinstated with the record that rejected them cited |
| Second direction | finer-groups chosen, checked against the history the selection cites, admitted, N=7 |
| Interruption | A third design run in its own process, killed after the host ran the tool and before the record; one pending attempt; host closed |
| Reopen | Live, N=7, three investigations, next action is to run design E52 |
| Resume | The same job re-run with its persisted keys: execution `registered`, the receipt the host already held, conclusion MET at 82.0 bp over 480 rows, three attempts in all, no pending attempt. Nothing ran twice |

The expectation was written to be tested, not to fail; both the first
and the placebo expectation happened to be met. No deliberately failing
case was manufactured. The unsuccessful-result control is exercised by
the local-documents path and the headline example, which this run does
not repeat.

## 5. What this shows and what it does not

Shown: the expectation on the record before the analysis; the result
equal to the direct run; the next question chosen from candidates the
conclusion produced; earlier rejections holding candidates back and new
evidence bringing them back, with the records cited; an interrupted
attempt resumed after the host was closed and reopened without running
again; the whole cost in lines and seconds.

Not shown: adoption of an existing workflow, because none was supplied;
a negative result on this data; a user's own CSV, which needs a setup
whose source is declared historical, which the generator can write and
the runner does not yet take as a flag; a human's configuration time.
